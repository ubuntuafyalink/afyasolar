# Model evaluation

Published so the forecasting claims can be checked without retraining. Source of
record is the model card at
[`afyalink/afyasolar-chronos-48m-climate-ea-v1`](https://huggingface.co/afyalink/afyasolar-chronos-48m-climate-ea-v1);
the numbers below are transcribed from it.

## Climate forecasting

**Method.** AutoGluon three-window rolling backtest over the East Africa daily
series described in
[`afyalink/afyasolar-nasa-power-east-africa`](https://huggingface.co/datasets/afyalink/afyasolar-nasa-power-east-africa).
Metric is Weighted Quantile Loss. Lower is better.

| Horizon | SeasonalNaive | Chronos zero-shot | Chronos fine-tuned |
|---|---|---|---|
| Monthly | 0.253 | **0.162** | 0.163 |
| Daily | 0.110 | **0.053** | 0.053 |

**What this shows.** Chronos beats the seasonal-naive baseline by roughly 36% at
the monthly horizon and 52% at the daily horizon. That gap is the result worth
citing.

**What it does not show.** Fine-tuning on East African data did not improve on
the zero-shot model. Monthly got marginally worse, daily was unchanged. The
serving path therefore uses the zero-shot predictor. We publish the fine-tuned
weights anyway because the training pipeline is part of the open release and
because a negative result is still a result, but no claim of fine-tuning benefit
should be made on this evidence.

## Predictive maintenance

Remaining useful life and anomaly detection have **no published evaluation
numbers**, because there is no real telemetry to evaluate against. Both models
are trained on synthetic telemetry generated by
`ai-service/pipeline/synthetic/generate_telemetry.py`, and the serving path
simulates its own input window when none is supplied. Treat these endpoints as a
working method awaiting real data, not as a validated predictor.

Once the field telemetry described in the root README arrives, this section
should carry held-out metrics against real failures.

## Reproducing these numbers

```
cd ai-service
pip install -r requirements-serve.txt
python pipeline/eval/backtest.py
```

The script writes `backtest_report.md`, `leaderboard.csv` and
`per_variable_metrics.csv` into the predictor output directory. Those outputs are
gitignored because they are large and regenerable, which is why this summary
exists in the repository.

**Caveats on exact reproduction.** The training dataset is defined as "2000 to
present", so it grows over time and a rerun will not reproduce these figures
exactly. No random seed or hardware profile is currently pinned. Pinning a
dataset snapshot and a seed is open work.
